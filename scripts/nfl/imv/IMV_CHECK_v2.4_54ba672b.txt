 R-1 COLUMN PARSE BINDS THE WRONG SELECT (blocking).
  - csv_columns_from_sql (l.386-413) strips "--" comments, then takes the FIRST "SELECT" and the first "FROM" after it.
  - In SQL v3 the first SELECT is the sched CTE (SQL l.38). Its FROM is SQL l.40, which yields 9 aliases.
  - So len != 41 (l.451) and EVERY export is NOT_RUN with reason SQL_V3_COLUMN_COUNT. This fails safe but leaves the reader unusable.

  - MANIFEST l.13 says the SQL bytes are not on Cursor's clone, so this was never exercised against the real file.
  - Fix: parse the outermost SELECT list of the COPY query with depth-aware FROM detection, or pin an explicit 41-name tuple in v24 plus an assertion that it equals the parsed v3 aliases. Either way the result must be the SQL l.60-102 order, which is plan v2.1 l.16 (40 cols plus roof_vocab_unknown after roof_dome).
